# Tutora — MVP AI-репетитора (аналог Astra AI)

Це робочий каркас застосунку зі стеком **React + Vite + TypeScript + Supabase**,
той самий, що вже показав себе робочим у проєкті Linguo.

## Що вже реалізовано

- **Вхід** через magic-link на пошту (Supabase Auth), без паролів.
- **AI-чат репетитор** (`/tutor`) — використовує сократівський метод: за
  замовчуванням підводить студента до відповіді кроками, а не одразу видає
  готове рішення; якщо студент явно просить фінальну відповідь, надає її
  (див. системний промпт в `supabase/functions/ai-chat/index.ts`).
- **Письмо** (`/writing`) — банк тем на письмо по рівнях A1–B2
  (`src/lib/writingPrompts.ts`, легко розширити кнопкою «Ідея для тексту»).
  Студент пише текст, AI повертає оцінку 0–100, список сильних сторін і
  окремі граматичні виправлення (`original → suggestion` + пояснення).
- **Сфотографуй завдання** (`/snap`) — розпізнає задачу з фото і пояснює
  повне рішення крок за кроком.
- **Мій план** (`/plan`) — теми та відсоток засвоєння, які оновлюються
  автоматично після кожного заняття з репетитором чи вправи на письмо.
- **Серверний ліміт запитів** — 20 AI-запитів на день на користувача
  (налаштовується, див. нижче), перевіряється виключно на сервері.
- **Захист даних**: жодна таблиця не читається/пишеться напряму без RLS;
  усі привілейовані операції — через `SECURITY DEFINER`-функції з перевіркою
  `auth.uid()` і явним `search_path`.
- **Жодних AI-ключів у фронтенді** — весь виклик AI-провайдера відбувається
  в Supabase Edge Functions, ключ живе лише як серверний secret.

## Чого немає навмисно (за завданням)

- Оплати/підписки — лише каркас під майбутні ліміти.
- Reading/Listening режими, соціальні фічі — не входили в MVP.
- Готової бази словника/контенту — предмети і теми створюються по ходу занять.
- Автоматизованих e2e-тестів проти реального Supabase (описано нижче, що саме
  не перевірено).

## Як запустити БЕЗ термінала і без CLI (повністю в браузері)

Якщо не хочеш встановлювати Supabase CLI чи Claude Code — усе нижче робиться
мишкою в браузері.

### 1. База даних (Supabase, ~10 хв)
1. Зареєструйся на [supabase.com](https://supabase.com), створи новий проєкт.
2. Відкрий **SQL Editor** → New query, встав вміст файлу
   `supabase/migrations/0001_init.sql`, натисни Run.
3. Повтори те саме для `0002_rls_policies.sql`, потім `0003_writing_module.sql`
   (саме в цьому порядку).

### 2. Серверні AI-функції (теж у Supabase, без CLI)
1. У меню зліва відкрий **Edge Functions** → Deploy a new function.
2. Створи функцію з назвою `ai-chat`, встав у редактор увесь вміст файлу
   `supabase/functions-dashboard-ready/ai-chat.ts`, натисни Deploy.
3. Так само створи `ai-writing` (файл `ai-writing.ts`) і `ai-solve`
   (файл `ai-solve.ts`) з тієї самої папки `functions-dashboard-ready/`.
   Ці файли самодостатні — не потребують окремих `_shared`-файлів.
4. У **Project Settings → Edge Functions → Secrets** додай
   `GEMINI_API_KEY` — безкоштовний ключ без картки, отримати за 1 хвилину на
   [aistudio.google.com/apikey](https://aistudio.google.com/apikey).

### 3. Фронтенд (без npm install на своєму комп'ютері)
1. Створи безкоштовний акаунт на [github.com](https://github.com), натисни
   "New repository", встав туди файли проєкту через "uploading an existing
   file" (можна перетягнути мишкою весь вміст папки `astra-tutor`, крім
   `supabase/functions-dashboard-ready/`, яка не потрібна фронтенду).
2. Зареєструйся на [netlify.com](https://netlify.com) або
   [vercel.com](https://vercel.com), натисни "Import project" і вибери
   щойно створений GitHub-репозиторій — застосунок збереться в хмарі
   автоматично, без встановлення чогось на твій комп'ютер.
3. У налаштуваннях проєкту на Netlify/Vercel (Environment variables) додай
   `VITE_SUPABASE_URL` та `VITE_SUPABASE_ANON_KEY` зі свого проєкту Supabase
   (Settings → API). Перезапусти деплой.

Готово — застосунок буде доступний за посиланням, яке видасть Netlify/Vercel.

## Альтернатива: через термінал / Claude Code (для порівняння)

1. **Створи проєкт на [supabase.com](https://supabase.com)** (безкоштовний план).
2. У SQL Editor виконай по черзі файли з `supabase/migrations/`
   (`0001_init.sql`, потім `0002_rls_policies.sql`, потім `0003_writing_module.sql`).
3. Встанови [Supabase CLI](https://supabase.com/docs/guides/cli) і задеплой функції:
   ```bash
   supabase functions deploy ai-chat
   supabase functions deploy ai-writing
   supabase functions deploy ai-solve
   supabase secrets set GEMINI_API_KEY=...
   ```
   (Безкоштовний ключ без прив'язки картки — на
   [aistudio.google.com/apikey](https://aistudio.google.com/apikey).)
4. Скопіюй `.env.example` → `.env.local` і встав `VITE_SUPABASE_URL` та
   `VITE_SUPABASE_ANON_KEY` зі свого проєкту (Settings → API).
5. Встанови залежності й запусти:
   ```bash
   npm install
   npm run dev
   ```

Якщо це звучить складно — онлайн-курси Supabase CLI чи будь-який
frontend-розробник виконає кроки 1–3 за одну сесію; кроки 4–5 тривіальні.

## Безкоштовний доступ — що це реально означає

- **AI-провайдер**: Gemini API має справді безкоштовний рівень (без картки),
  але з лімітами від Google (кількість запитів на хвилину/день на один
  ключ). Для тебе особисто і кількох друзів цього вистачить з запасом.
  Якщо застосунком раптом почне користуватись багато людей одночасно —
  Google почне відповідати помилкою `429`, і твої користувачі побачать
  контрольоване повідомлення "AI-сервіс тимчасово недоступний" (а не
  поламаний застосунок) — це вже оброблено в коді.
- **Хостинг**: Supabase (безкоштовний план) і Netlify/Vercel (безкоштовний
  план) — обидва мають власні щедрі, але не безмежні ліміти. Для особистого
  проєкту й кількох користувачів безкоштовних планів достатньо.
- **Надання доступу іншим людям**: реєстрація в застосунку відкрита для
  будь-кого — просто даєш людині посилання на застосунок (те, що видасть
  Netlify/Vercel), вона вводить свою пошту і отримує лист для входу. Ти
  нічого додатково не налаштовуєш. Якщо захочеш згодом обмежити коло людей
  (наприклад, лише за запрошенням) — це окрема невелика доробка, якої зараз
  немає.
- Ліміт **20 AI-запитів/день на людину** (не на весь застосунок) — це і
  захищає безкоштовні ліміти Gemini від випадкового вичерпання одним
  користувачем. Змінити число можна в будь-який момент (див. нижче).

## Конфігурація ліміту AI-запитів

Ліміт зберігається в таблиці `app_config`, ключ `daily_ai_request_limit`
(за замовчуванням 20/день). Змінити:
```sql
update public.app_config set value = '50' where key = 'daily_ai_request_limit';
```
Ліміт застосовується виключно на сервері всередині `increment_ai_usage()` —
фронтенд лише показує поточне значення, ніколи не вирішує, чи дозволено запит.

## Не перевірено / потребує уваги

- Едж-функції не тестувались проти реального задеплоєного Supabase-проєкту
  в цій сесії (немає мережевого доступу в середовищі розробки) — перед
  продакшеном обов'язково прогнати вручну сценарій: реєстрація → чат →
  письмо → ліміт → фото-розв'язання.
- Автоматизованих unit/integration тестів у цьому MVP ще немає.
- CORS у `_shared/cors.ts` наразі відкритий (`*`) — звузь до свого домену
  перед публічним запуском.
- Snap & Solve наразі не зберігає історію фото-запитів (лише повертає
  відповідь) — усвідомлений мінімальний обсяг MVP.
